# 주간 배너 추천 시스템 설계

학교 대표 공지사항(행사, 수강신청, 예비군 등)을 매주 자동으로 선별하여 Discord로 전달하는 시스템 설계 문서.
관리자가 수동으로 배너를 고르는 대신, 스코어링 파이프라인과 Claude API가 추천 후보를 생성하고 Discord로 전달한다.

---

## 전체 흐름

```
[주간 스케줄러 (매주 월요일 오전 9시)]
        ↓
[1차: 규칙 기반 스코어링]  ← DB에서 최근 공지 조회
  - 조회수 / trending 점수
  - 키워드 매칭 (수강신청, 행사, 이벤트, 예비군 등)
  - 카테고리 가중치
  - 날짜 근접도 (이번 주 예정 행사 우선)
        ↓
[2차: Claude API 스코어링]  ← 상위 N개 공지 텍스트 전달
  - 배너 적합성 판단 + 이유 요약
  - 추천 순위 재정렬
        ↓
[Discord Webhook 발송]
  - 상위 3~5개 추천 배너 후보 + 이유 + 링크
  - 관리자 확인 후 직접 배너 등록
```

---

## 구성 요소

| 구성 요소 | 신규 여부 | 비고 |
|---|---|---|
| `BannerRecommendationScheduler` | 신규 | `@Scheduled(cron = "0 0 9 * * MON")` |
| `BannerScoringService` | 신규 | 규칙 기반 1차 스코어링 |
| `ClaudeRecommendationClient` | 신규 | Claude API 호출 |
| `DiscordWebhookClient` | 신규 | Webhook POST |
| Discord Webhook URL | 설정 | `application.yml`에 추가 |

## Claude API 토큰 최적화 전략

### 1. 입력 토큰 최소화

**공지 텍스트 전처리**
- 본문 전체가 아닌 `title + category + date + 본문 앞 100자`만 전달
- HTML 태그, 첨부파일 목록 등 노이즈 제거 후 전달

**1차 필터링 강화**
- 규칙 기반 스코어링으로 DB에서 상위 5~10개만 추출하여 Claude에 전달
- 호출 전에 뻔히 부적합한 공지를 최대한 제거

**시스템 프롬프트 캐싱 (Anthropic Prompt Caching)**
- 역할 정의, 판단 기준, 출력 형식 지침 등 고정 부분에 `cache_control: ephemeral` 적용
- 매주 반복 호출 시 시스템 프롬프트 토큰을 약 90% 절감 (캐시 히트 시 0.1x 비용)

### 2. 출력 토큰 최소화

**구조화된 출력 강제**

```json
// 나쁜 예 - 자유 형식 응답 (토큰 낭비)
"이 공지사항은 수강신청과 관련된 매우 중요한 공지로..."

// 좋은 예 - JSON 강제
{"rank": 1, "id": 42, "reason": "수강신청 일정"}
```

- `max_tokens`를 명시적으로 제한 (예: 500 이하)
- 추천 이유를 15자 이내로 제한하도록 프롬프트에 명시

### 3. 호출 횟수 최소화

**단일 배치 호출**
- 후보 5개를 각각 호출(5회) 대신 한 번에 전달(1회)

**중복 처리 방지**
- 이미 배너로 등록된 공지, 지난주에 추천된 공지는 DB에서 사전 제외
- `recommended_at` 컬럼으로 재추천 방지

### 4. 모델 단계별 선택

```
[DB 후보 20개]
      ↓
[규칙 기반 → 상위 10개]   ← 비용 없음
      ↓
[Haiku로 5개 압축]         ← 저렴 (입력 $0.80/1M tokens)
      ↓
[Sonnet으로 최종 랭킹]     ← 필요 시에만
```

무조건 고성능 모델을 사용하지 않고, cheap → expensive 순서로 단계별 활용.

---

## 최적화 전략별 효과 요약

| 전략 | 절감 효과 |
|---|---|
| 시스템 프롬프트 캐싱 | 입력 토큰 ~90% |
| 1차 필터링 강화 | 입력 토큰 50~70% |
| 텍스트 트리밍 | 입력 토큰 30~50% |
| JSON 출력 강제 | 출력 토큰 60~80% |
| Haiku 1차 처리 | 비용 ~80% |

실질적으로 가장 효과가 큰 조합: **시스템 프롬프트 캐싱 + 1차 필터링 강화**
