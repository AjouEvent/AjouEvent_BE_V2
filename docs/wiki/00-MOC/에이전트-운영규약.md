## 신뢰 순서

실제 동작 판정은 **코드 > 정책서 > 화면 설계서 > 원문 자료** 순서로 확인한다. 근거: 이 위키의 `policies.json` 코드 추출 기준, `screens.json` 화면 추출 기준, `infra.json` precedence. 코드와 정책이 다르면 구현 차이로 [[구현현황-코드매핑]]에 적고, 정책을 조용히 고치지 않는다.

## 되쓰기 절차

1. 새 사실은 해당 주제의 정본 노트 한 곳에 근거와 함께 기록한다.
2. 다른 문서는 위키 링크로 연결한다.
3. 서로 다른 자료가 어긋나면 [[Q-확인필요]]에 양쪽 출처와 미정 상태를 남긴다.
4. `updated` 날짜를 고친다.
5. 링크·POL 개수를 검사한 뒤 이 저장소에서만 작업 단위로 커밋한다.

## frontmatter

모든 Markdown 노트에 `type / status / source / updated / tags`를 쓴다. `status: 확정`은 코드에서 확인한 사실에, `status: 미정`은 질문과 미해결 판단에 쓴다. 근거: 이 위키의 편찬 규칙.

## 콜아웃

- `> [!important]`: 읽기 규칙과 핵심 전제.
- `> [!warning]`: 출처 충돌 또는 미정.
- `> [!note]`: 배경과 측정 시점.

## Git

이 폴더는 자체 Git 저장소이고 원격이 없다. 수정한 파일만 커밋한다. 메시지는 `Docs: {한국어 요약}` 또는 `Chore: {요약}` 한 줄이다. push는 하지 않는다. 근거: 이 위키 작업 규칙.
